# 昨日头条 · 中国历史日签

只收录中国历史，以每天至少一篇有原文证据的日签为目标。真实网页检索 → DeepSeek 摘要 → 日期和连续原文校验 → 独立复核 → 日报与备稿。模型不以记忆补足条数，外国事件不因刊载于中国网站而合格。

## 每日流程

GitHub Actions 计划于北京时间 00:15、08:15、16:15 运行，平台可能延迟。每天先从已核验资料库和备稿恢复到期内容，再检索当天新资料；随后准备未来七天中最多两个缺稿日期，最后回补最近七天中最多两个空日。额外时段用于补救检索和外部服务故障。

检索按主题、机构、历史阶段分三层。扩展至科技、交通、水利、教育、医疗、文化体育、公共建设，使用政府部门、科研院所、高校官方资料及可信新闻机构。是否继续检索取决于通过全部校验的事件数，而不是网页数量或模型生成数量。

`source_hints.json` 保存按月日的官方原文链接及年表入口，只是检索线索；每个新条目仍须读取正文并经过同样的日期、连续引用、摘要事实和中国历史范围校验。禁止把网页发布日期当事件日期，禁止将标题年份与正文月日拼接。中国主体在境外的明确成就可以收录。

## 资料与发布

- `archives/YYYY-MM-DD.json`：今天及前六天的独立日报，共七天。已核验的历史日报保留；过期文件可从 Git 历史恢复。
- `prepared/YYYY-MM-DD.json`：提前核验的待用稿；不开放未来日期。前端只在今日正式日报缺失、为空或无效时，读取同日有效备稿。保留最近七天及未来七天共十四日范围。
- `catalog.json`：累积资料库，保留旧资料，但只有带合格原文日期证据的 `source-matched` 记录可以支撑每日最低篇数。未来备稿不推进出版日期和 `lastRun`。
- `archive_index.json`：七天出版索引；`lastRun` 代表最近成功采集，`lastAttempt` 只报告今天最近尝试，不把旧成功冒充本次成功。
- `issue.json`、`today_news.json`：今日输出与旧格式兼容。
- `coverage_status.json`：未来七天的已备好日期、缺稿日期及已核验年历覆盖数（全年按 366 个不同月日计）。只有真正齐备才会标记全年覆盖，不能由少量示例推断全年保证。
- `window_status.json`、`preparation_state.json`：当日最低篇数是否达到、失败日期、回补与备稿尝试记录。
- `collection_diagnostics/YYYY-MM-DD.json`：检索、引用校验、修正及复核诊断，成功失败都保存为 Actions 附件；不保存密钥、完整网页或模型响应。

没有合格新稿且也没有同日已核验记录时，本次采集失败，不以空日报冒充成功。成功内容仍会先保存；今日未达标或本轮历史回补失败会让 Action 显示失败。备稿缺口在覆盖报告中列出，并在后续运行继续尝试。自动校验不能保证零事实错误，每篇仍提供出处和证据供阅读核对。

## 运行边界

每个日期最多 15 条查询、48 个白名单 HTTPS 页面、18 份模型来源、9 次逻辑模型调用，每调用最多 2 次 HTTP 尝试。三层按剩余时间分配，单日期软预算 8 分钟；网络请求检查剩余预算，但不宣称操作系统级硬截止。调度 35 分钟后不启动额外日期，工作流最终上限 45 分钟。

每个历史日期在窗口内最多重试两次，同一北京时间日期内不重复回补。备稿对同一目标日期每天最多尝试三次，优先最临近缺稿日期；已有合格备稿不重复消耗模型调用。资料会在后续年份复用，逐步积累年历覆盖。

手动运行可选 `backfill_budget` 0–6（默认 2）、`prepare_budget` 0–7（默认 2），用于有上限地回补和初始化备稿。沿用 GitHub Secret `DEEPSEEK_API_KEY`，密钥不会进入前端或 JSON 文件。费用取决于实际调用次数和文本长度。

## 验证与手动运行

Python 3.12+：

```text
pip install -r requirements.txt
python -m unittest discover -s tests -v
python collect_history.py --retrieve-only
python archive_window.py --days 7 --backfill-budget 2 --prepare-budget 2
python archive_window.py --days 7 --finalize-only
```

仅检索与单元测试不需要模型密钥。正式采集和提前备稿在 GitHub Actions 内使用已有密钥执行。

发布任务开始时读取目标分支的最新资料，因此可以对新版任务使用 `Re-run all jobs`。GitHub 重跑旧任务时仍使用当时的工作流版本；本修复之前的旧任务请改用 `Run workflow` 在 main 上启动新任务。发布只做普通快进推送，不强制覆盖仓库；若运行期间有人提交了新版本，推送会安全拒绝，此时从最新分支重新运行即可。
